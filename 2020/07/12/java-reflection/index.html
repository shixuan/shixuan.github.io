Java反射

Java 的反射机制可以让我们在程序运行时动态构建一个对象，获取对象的属性、构造器以及方法。反射在绕过访问检查时可能破坏 Java 代码的封装性，因此需要谨慎使用，在框架中尤其常见。反射用得好，能把 JVM 掀个底朝天 (bushi

从 Java 代码到对象

假若我们当前有一个普通的 Java 类：

通过 javac 编译后，Wizard.java 会生成 Wizard.class 字节码文件。程序运行时，JVM 通过类加载器 ClassLoader 加载这个类，并创建一个对应的 Class 对象。

这里有两个不同的对象：Class 对象表示的是 Wizard 这个类，new Wizard() 创建的则是这个类的实例。我们可以创建很多个 Wizard 实例，它们各自有自己的 name、healthPoint 和 magicPoint，但只要属于同一个运行时类，获取到的 Class 对象就是同一个。

类加载之后，还需要经过链接和初始化，才能正常创建实例。链接包括验证字节码、为静态字段分配存储空间等工作；初始化会执行类的静态初始化代码。而 new Wizard() 会为新实例分配空间，并执行实例初始化和构造函数。

反射的入口就是这个 Class 对象。通过它，我们可以获取描述成员变量的 Field 对象、描述构造器的 Constructor 对象，以及描述方法的 Method 对象，再用它们读取属性、创建实例或调用方法。

而使用 getDeclaredMethods，只能获取到 Wizard 的所有方法：

也就是说，带有 Declared 的 get 方法只能获取到当前类的变量和方法，不管是 public 修饰的还是非 public 修饰的。而不带有 Declared 的普通 get 方法能获取到自己、父类及父类以上的所有 public 修饰的变量和方法 (方法被重写时不会把父类版本也全部列出，也会考虑继承的接口成员)。对于 Constructor，不管用什么，都只能获取到当前类的构造器。
