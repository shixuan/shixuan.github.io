Reference collapse and perfect forwarding

转发问题

假设我们有一个工厂函数，它会创建一个对象并返回，同时将接收到的参数传递给对象的构造函数：

这样实现会有两个问题，

  1. 无法接收右值：参数被声明为左值引用 Args&...，因此不能绑定到右值，例如临时对象或整数字面量。比如 make<int>(42) 无法通过编译。
  2. 丢失移动语义：即使将参数改为 Args&&... 以同时接收左值和右值，在 make 函数内部，每个有名字的参数 args 作为表达式时都是左值。因此直接使用 args... 会把所有参数都以左值传递给 T 的构造函数，无法保留调用者传入时的左值/右值特性。当构造函数对左值和右值有不同重载时，右值对应的重载 (例如移动构造函数) 不会被调用。

所以，我们需要一种方案，来接收可推导的左值或右值参数，并且在转发时保留其左值/右值性质和 const 等限定。

Reference collapsing

c++ 不允许直接写出 “引用的引用”，例如 int& &。但通过模板参数、类型别名等间接形成这种组合时，会发生引用折叠。c++11 中的规则如下：

  • T& & --> T&
  • T& && --> T&
  • T&& & --> T&
  • T&& && --> T&&

也就是说，只有两个右值引用会被折叠为右值引用，其他情况都会折叠为左值引用。

Universal references

万能引用是基于引用折叠实现的，其形式和右值引用一样，都是 &&。万能引用能同时匹配左值和右值。

这里的万能引用 (标准中称为转发引用) 要求 T&& 中的 T 是参与本次函数调用类型推导的、没有 const/volatile 限定的模板类型参数。auto&& 在通常的类型推导中也有类似作用 (花括号初始化列表除外)。

假设实参的类型为 A。当传入的是左值时，T 被推导为 A&，参数类型变为 A& &&，折叠后为 A&；当传入的是右值时，T 被推导为 A，参数类型为 A&&。这里 A 保留实参的 const/volatile 限定。
