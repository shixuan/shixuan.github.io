Devlog 0006 — 为 Hexo 接入 Decap 网页写作后台

Context

原来的写作流程是本地编辑 Markdown，提交到私有源码仓库，再由 GitHub Actions 运行 Hexo，将生成的静态文件发布到公开站点。想加一个网页编辑入口，出门时也能写文章、存草稿，同时继续使用现有的文件格式、Git 历史和部署流程。

最后接入 Decap CMS：编辑器在浏览器里运行，直接通过 GitHub API 管理 Markdown；登录认证交给独立的 Cloudflare Worker；文章发布仍然走原来的 CI。

Implementation

HTML 加载程序，YAML 描述内容

Decap 是完整的前端应用。博客只需要一个入口 HTML，加载固定版本的 Decap JavaScript，再提供同目录的配置文件。编辑器、文章列表和发布按钮都由 Decap 生成。

配置文件描述仓库后端、文章目录，以及标题、日期、标签、分类、正文等字段。Decap 根据这些字段生成表单，并把编辑结果写回 Markdown 的 YAML front matter 和正文。

后台文件放在 Hexo 的 source 目录中，通过 skip_render 原样复制到构建产物。因此，后台使用 Decap 自己的界面，不套 Icarus 主题；发布出来的文章仍由 Hexo 和 Icarus 渲染。界面语言设置为英文。

这里没有引入保存文章内容的数据库。Git 仓库仍然是内容来源，本地编辑和网页编辑可以并用。

Worker 只负责登录认证

登录时，Decap 打开 GitHub 授权窗口。用户同意后，GitHub 把临时授权码送到预先登记的回调地址；Worker 在服务端交换访问令牌，再通过弹窗消息交给 Decap。之后读取文章、创建提交和合并 PR，由浏览器中的 Decap 调用 GitHub API 完成。

这次实现对登录请求使用随机 state 和 PKCE 校验，通过短期、HttpOnly、Secure 的 cookie 关联浏览器会话。回传令牌时同时检查消息来源和窗口身份，只发送到配置的编辑器来源。认证响应禁用缓存，应用密钥保存在 Worker secrets 中。

回调地址是公开的服务入口，不是凭证。需要保护的是应用密钥、临时授权码和访问令牌，不能把它们写进文章、静态配置或调试日志。Decap 最终需要在浏览器中持有令牌，所以后台脚本和浏览器环境仍然属于信任边界。固定脚本版本用于控制升级，并不意味着第三方脚本没有风险。

私有仓库的传统 OAuth 接入使用 repo scope，权限范围并非只限于这一个博客仓库。这是当前方案的取舍，不能把配置中的仓库路径当作令牌的权限边界。

草稿使用分支和 PR

启用 Decap 的编辑流程：

保存草稿时，内容进入独立分支，并产生 PR；点击发布后，变更合并到发布分支，触发原来的 CI。这样可以多次保存，不必每写一点就更新公开博客。

这里的草稿机制与 Hexo 的 source/_drafts/ 无关，也不依赖给文章填一个未来日期。日期字段仍是文章元数据，不能代替定时发布任务。

适配已有文章

博客的文章链接由年月日和 id 组成，因此编辑旧文章时要保留这两个字段。新文章使用唯一的 id 生成文件名；已有文章中包含加号的标识也需要通过校验，避免为了适配后台而改变旧链接。

标签和分类使用简单列表控件，兼容已有的单个字符串和数组写法。保存时字符串可能被序列化成数组；分类数组在 Hexo 中表示分类层级，需要按原来的含义填写。

正文采用 Markdown 源码模式，便于保留 Hexo 特殊语法和摘要分隔符。图片直接粘贴图床链接，缩略图字段也填写 URL。这次没有接入图片上传，也没有调整已有的网页资源目录。

编辑器里的预览只是写作参考，不是完整的 Icarus 页面预览。最终排版仍以 Hexo 构建结果为准。

给预览补上 MathJax

博客主题已经加载 MathJax，但 Decap 预览运行在独立的 iframe 中，不会继承主题的公式渲染。只在后台多加载一个 MathJax 脚本也不够：正文先经过 Markdown 解析，公式里的反斜杠和下划线可能已经被改写。

这次通过 Decap 的 registerPreviewTemplate 注册文章预览。先用 markdown-it 和数学语法插件把 TeX 从普通 Markdown 中识别出来，保留公式原文，再用 MathJax 3.2.2 转换为 SVG。SVG 不依赖预览 iframe 之外的字体缓存，便于放进独立文档。

预览支持行内的 $...$、\(...\) 和独立公式的 $$...$$、\[...\]，代码块及行内代码保持原样。表单增加 MathJax 开关，新文章默认开启；这个开关控制后台预览，公开页面仍由主题的全局配置决定是否加载 MathJax。

实时编辑时稍作延迟再排版，公式转换串行执行，并检查当前内容版本，避免较慢的旧渲染覆盖最新正文。React 管理预览容器，渲染逻辑管理容器内部的内容，防止两者同时修改公式节点。这些处理只影响预览，不会重写文章源文件。

接入后还遇到过公式看起来重复显示的问题。SVG 转换结果中附带了供屏幕阅读器使用的 MathML，而预览 iframe 没有带上 MathJax 的完整样式，辅助内容也被浏览器画了出来。修复是在预览文档中安装 MathJax 生成的样式表，让辅助内容按预期视觉隐藏，同时保留可访问性。检查时除了统计公式节点，也需要看实际显示效果和辅助节点的计算样式。

依赖使用固定 CDN 版本。原始 HTML 按文本展示，Hexo 标签不在预览中执行；MathJax 加载或转换失败时保留未排版的内容并显示提示。公式预览依然不是完整的主题预览。

Verification

本地构建检查确认后台 HTML 和配置原样输出，并检查现有普通文章的 id 是否符合后台校验规则。认证代码用模拟 GitHub 响应和窗口消息的测试覆盖正常交换、无效或过期的登录状态、错误来源消息以及上游失败。

线上用测试文章完成了 GitHub 登录、读取文章列表、保存草稿、生成 PR 和正式发布验证。发布后 CI 正常生成博客页面，网页写作与原来的静态部署流程接通。

公式预览另外做了本地浏览器验证，检查行内与独立公式、矩阵、代码示例、HTML 转义、连续编辑和开关切换。两篇现有数学文章分别转换出 20 个和 7 个公式，没有 TeX 错误；实际 Decap 入口的依赖加载也通过检查。这部分属于本地验证，不能代替部署后的浏览器检查。

Notes

日常操作变成：打开编辑器，写 Markdown，保存草稿，准备好后发布。回到本地写作前先同步远端提交，避免本地文件落后于网页上的修改。

升级 Decap 时显式更新固定版本，并重新检查登录、旧文章字段和草稿发布流程。公开记录只保留架构与配置原则，实际仓库标识、认证域名和凭证不作为示例展开。
